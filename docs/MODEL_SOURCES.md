Runtime sources in `scripts/setup-runtimes.sh`: [whisper.cpp v1.9.5](https://github.com/ggml-org/whisper.cpp/tree/v1.9.5), source-archive SHA-256 `ff1a9053feb509ff9d7729703355541ae9690073a6b1c40eb692c962e0dc1720`; [llama.cpp v0.6.0](https://github.com/ggml-org/llama.cpp/tree/v0.6.0), source-archive SHA-256 `09b36dba235fcac180efff18514da7038e65d8e5b9e4aefa59238468abfdec12`; [transcribe.cpp v0.4.1](https://github.com/handy-computer/transcribe.cpp/tree/v0.4.1) (commit 4d7c1cc), source-archive SHA-256 `96a3993c075770bf3ca7aeaa86cc55c3673c24d7176643b60cc6a1f46dcab4a5`, built without system BLAS. All three use their upstream MIT licenses; transcribe.cpp lists the code it includes in its `THIRD-PARTY-LICENSES.md`. The worker uses only the Python standard library (the system python3 on Linux, the bundled embeddable CPython on Windows), so nothing is installed from PyPI. The app never installs anything at normal startup; explicit onboarding downloads or imports only the selected models. No credentials are accepted or logged. C++ engines are included in the Linux package; only maintainers compile them.

Model-weight download sizes are separate from RAM. We measure RSS independently and make no mobile/Arm benchmark claim for this x86_64 build.

VoxLoom 0.1.2 applies the small, reproducible `scripts/patch-llama-completion.py` delta after verifying/extracting the pinned llama.cpp archive. The completion frontend parsed `--reasoning off` but omitted `enable_thinking` and `chat_template_kwargs` when formatting the initial prompt. The patch forwards these two fields. Both optimized and generic completion executables are rebuilt from that patched source; upstream copyright/license notices remain intact. No model weights are modified.
