# VoxLoom architecture

VoxLoom runs on Linux and Windows 11 x64 from one codebase. This document describes the shared architecture. Where the platforms differ, the capture details below describe the Linux PulseAudio/PipeWire backend; Windows uses WASAPI microphones and output loopback, with the same FLAC segments and the same host/worker split. The Windows runtime, installer and platform code are described in [WINDOWS.md](WINDOWS.md).

Tauri 2 hosts a React/TypeScript bundle in the system webview: WebKitGTK on Linux and WebView2 on Windows. No Electron, network font, CDN, account, updater, telemetry, cloud SDK, or runtime HTTP server. The only requests are the ones the user clicks for: model setup downloads, and Settings → Updates → Check for updates, which asks GitHub's API for the latest published release (`worker/updates.py`) and, if it is newer, opens that release page in the browser; nothing is downloaded or installed for it. End-user onboarding presents one download-and-setup action; paths, engine details and diagnostics are hidden under advanced settings. The floating recorder resizes this same webview to 390×92 and restores the studio. Some Wayland compositors may limit always-on-top or positioning requests.

The Rust host owns lifecycle, private data directories (XDG on Linux, `%LOCALAPPDATA%` on Windows), SQLite WAL/FTS5, imports/exports, the inference queue, and capture. On Linux that capture is PulseAudio/PipeWire; on Windows it is WASAPI. `audio.rs` is the platform boundary for future capture backends. PipeWire's Pulse compatibility socket works on Wayland without an X11 capture API. `pactl` discovers real inputs and output monitors; the app never creates a virtual sink or modifies routing. FFmpeg records selected sources to separate 16 kHz mono FLAC tracks, segmented every 30 seconds. This preserves speech and bounds recovery windows; it is not archival full-bandwidth stereo recording. Tracks share a capture session and approximate timestamps; device latency/sample-accurate alignment is not calibrated. Pause closes and flushes the active files; resume starts a new session with a persisted offset. Storage chunks do not define transcription utterances. ASR joins each source/session logically using decoded sample durations. FFmpeg flushes every FLAC frame (`flush_packets=1` on the segment muxer), so while recording the host polls live transcription every 2.5 seconds and the worker also reads the file still being written, up to its last CRC-valid frame; that file is never registered or cached until it closes. Chunk boundaries come from pauses, not files or clocks: speech-band (250–3800 Hz) frame levels are compared with an adaptive noise floor (the quietest 2-second stretch, at least −75 dBFS), so fan/hum noise on a laptop microphone does not hide pauses. A chunk ends inside a pause of at least 1 s, or 0.6 s once it holds 10 s of audio, or a 0.35 s breath once it holds 16 s; nonstop speech is divided at its quietest moment so no chunk exceeds 28 s (one Whisper window). Chunks never overlap, so no text is deduplicated by guesswork. Only digital silence, or audio with clear voice/pause contrast and no voiced frames, is skipped without Whisper; audio without that contrast (a music bed, nonstop speech) is always transcribed. Whisper can end a window early when it judges quieter trailing speech to be silence. After each chunk, voiced stretches with no returned words are decoded again (the last segment plus the missed tail together, else the missed stretch alone with a fuzzy seam check), so skipped speech becomes a retry instead of a gap. Rows are sentences: an unfinished final sentence is carried in the stream checkpoint and completed by the next chunk, or flushed after a silence, at 300 characters/30 seconds, or at Stop/Pause (both queue a final pass). Full decoded segments are retained; approximate timestamps only place rows on the timeline and are never used to discard text. Per-source/session coverage, the pending sentence and the noise floor are committed atomically with transcript batches (stored as JSON in `asr_progress.overlap_text`). Previous text is not passed to Whisper as a prompt, because transcript text never appears on a command line. FLAC segment durations are cached after counting decoded PCM, and segmented files are decoded before seeking to avoid inherited-header/seek errors. Any final tail is queued after stop, including when another ASR batch is already in flight. Imports auto-transcribe when available, and completed ASR automatically queues search preparation; summaries never auto-run. After a crash or power failure the recording is marked interrupted; on restart its segment files (including the one that was still being written) are registered, a final pass is queued for whatever no pass had read or an unfinished sentence left in the checkpoint, and the decoded lengths restore the recording's duration. Only audio FFmpeg had not yet flushed is lost. A segment cut off before its first complete frame (a crash within the first fraction of a second of a new file) cannot be opened by FFmpeg at all; the worker counts it as empty rather than failing the pass over the segments recorded before it. A live pass registers any segment that closed since the scheduler's last poll before it reads the growing file, so the stream it sees has no gap.

## Local inference and memory

One heavy job runs at a time, and none while a recording is open, paused included: each recording is transcribed in one pass after Stop, over the whole recording, so every cut can wait for the best pause. Starting a recording stops a running worker; its job waits, and a transcription resumes from its last checkpoint. The durable SQLite queue is bounded at eight pending/running jobs, except transcriptions, which are never turned away. Transcription has priority over indexing and summaries. Each job starts a private Python child using file-based JSON input and streamed JSONL results. Text/audio content is never encoded into a command line or shell string. Audio moves through bounded local WAV files. Results are ingested incrementally by the single Rust connection. Completed embedding chunk keys persist and are skipped on retry. Revision/dimension/backend/chunk-version mismatches trigger rebuilding the affected model's index without deleting recordings.

Whisper Base English runs through a locally built `whisper-cli`. LiteRT-LM 0.18.0 directly calls `EmbeddingEngine` on the full 740M checkpoint, explicitly enabling the CPU audio encoder for audio jobs and leaving the vision backend unset. Text queries/documents receive their distinct documented task prefixes. Native audio embeddings do not depend on a transcript. All 768 components must be finite; vectors are normalized and stored as little-endian float32 BLOBs in SQLite. A bounded top-k linear cosine scan suits a modest personal library. FTS5 exact search is independent; combined search uses reciprocal rank fusion. Overlapping results are deduplicated within each modality.

Summaries are exclusively user-triggered. Importing/finishing a recording never queues a summary. Settings selects Gemma 4 E2B (default, part of the standard download), optional Gemma 4 E4B, or an explicitly imported custom GGUF. Gemma 3 1B was removed in 0.1.8; a saved `1b` choice resolves to E2B (`service.rs::summary_profile`). The pinned llama.cpp v0.6.0 `llama-completion` executable is used because the upstream `llama-cli` has evolved into a different frontend. Native GGUF chat templates are applied with `--jinja --reasoning off`; the pinned completion frontend has a documented two-line patch forwarding its parsed reasoning/template options into prompt formatting. Completed result wrappers or native end-of-generation markers are required; unfinished thought channels are rejected and old saved drafts are hidden with a regeneration notice. context is limited to 4096 tokens and generation to 768 tokens per batch, CPU only. Long transcripts use bounded map/reduce passes. These passes can reload the model between batches: a tradeoff for deterministic unloading. Note generation uses plain transcript text and the prompt for the chosen summary style (Counselling by default; Service, Meeting, or the user's own instructions wrapped in the same safety rules). Section titles are stored as `## ` lines. The final pass also suggests a title, which replaces only the default "Untitled recording". It stores normal section titles, paragraphs and bullets without source timecodes; empty sections and questions not explicitly raised are omitted. The Transcript tab retains recording timestamps. Q&A uses a small retrieved evidence window and continues to normalize/validate its citations, falling back to labeled evidence extracts when citations fail. Citation validation is not factual verification of every sentence. All model output requires human review.

Workers exit when a job completes; no model is preloaded or held idle. A process-group supervisor kills inference descendants on cancel/Quit, waits/reaps workers, and flushes/stops capture before desktop exit. Linux parent-death signals protect against an unexpectedly killed host; on Windows a kill-on-close Job Object contains the app and every process it started. Python decoder/ASR/LLM children also receive a parent-death signal on Linux. Runtime network/autodownload flags are disabled. Temporary request/chunk folders are removed on completion and scavenged on startup after interruption. Private folders are mode 0700 and the native host sets umask 077 on Linux; Windows AppData is already private to the account. No routine logs contain transcripts or PCM. SQLite uses secure_delete; normal deletion is not a forensic secure-erase guarantee.

## Models and provisioning

`models/manifest.json` pins official repository revisions, exact filenames, sizes, SHA-256 hashes and license links. `worker/provision.py` downloads model files and `worker/setup_runtime.py` installs the pinned LiteRT environment. Both run only after explicit setup approval; neither runs at startup. The simple first-run button supervises these steps sequentially. CPU C++ engines and generic fallbacks are bundled; CPU capability probing selects the optimized executable where supported. Standard setup is Whisper + 740M EmbeddingGemma + optional Gemma 4 E2B summaries. The manifest's `retired` list names files earlier versions installed; `models()` reports them only while they are on disk, so Settings can remove them, and nothing ever downloads them. It supports offline check/import, streaming download progress, Range resume, cancellation and independent retry. Imports and completed downloads verify hashes before atomic rename. Known default filenames are revalidated before inference: a file is hashed once, then trusted while its size and modification time match the record in `<cache>/verified-models.json` (hashing the 2.8 GB summary model on every pass cost seconds each); custom GGUFs are explicitly unverified. A partial download that the server will not resume, or that fails its hash, is deleted so a retry starts clean. No model is bundled in Git or the application package.

Settings can remove downloaded models to free disk space (`remove_models`). It deletes only manifest filenames in the model folder, their `.part` downloads and the matching LiteRT `*.xnnpack_cache` files in the cache folder; a custom GGUF is never touched. It holds the inference lock and the capture lock while deleting and refuses while recording, during setup, or while any job is pending or running, so no job or live transcription loses its model mid-run. Recordings, transcripts, embeddings and settings are kept; a selected profile whose file is gone reports the model as unavailable until it is downloaded again.

## Boundaries and remaining work

The bridge accepts named commands and validated local paths, with a restrictive production CSP. Media asset access starts empty and grants exact paths returned by Rust. No frontend filesystem/shell/network plugin is exposed. Export refuses to overwrite managed library/cache files. Record deletion cascades through transcript, FTS, audio references, vectors and jobs and removes the recording's private directory.

Physical-device hotplug, long meetings, full disk, cross-device drift, secure sandbox packaging, and business summary quality still require extended validation. Local language code is configurable; the supplied default ASR model is English. Speaker labels identify tracks, not people. Playback automatically advances through the selected source’s chunks and provides one recording timeline. Audio export joins that source’s chunks. A synchronized mic+system playback mix is not implemented. OS minimize is separate from true Quit: Quit stops all work and releases models.

Meeting notes render as semantic headings, paragraphs and lists. **Copy notes** supplies both styled HTML and plain text to the desktop clipboard for Word; **Copy Markdown** supplies plain-text Markdown built from the same parsed blocks (`MeetingNotes.tsx::meetingNotesMarkdown`), so the two never disagree. The summary page has no Word export; the transcript's Word export remains. Word exports use a short, supervised Python standard-library OOXML/ZIP writer; no office suite or model is loaded for export, and no external links or macros are embedded. Word is the normal document format in the UI; legacy Markdown/JSON exports remain in the backend for compatibility and developer workflows.
